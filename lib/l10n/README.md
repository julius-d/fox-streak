# l10n (issue #003)

`app_en.arb` / `app_de.arb` are the source of truth for all app copy (EN +
DE). `app_localizations.dart` + `app_localizations_en.dart` +
`app_localizations_de.dart` are generated by `flutter gen-l10n` (driven by
the root `l10n.yaml`, triggered automatically by `pubspec.yaml`'s
`flutter: generate: true`) — **do not hand-edit them**, they're
regenerated (and overwritten) on every `flutter build`/`flutter run`/
`flutter test`/`flutter analyze`/`flutter pub get`.

To pick up new or changed arb keys: edit `app_en.arb`/`app_de.arb`, then
run any of the commands above (or `flutter gen-l10n` directly) and commit
the regenerated files alongside your arb changes, same as the `drift`
`*.g.dart` convention.

## History: why this used to be hand-written

For a while (commit `460d0fb` through issue #061), this repo carried a
**hand-written** `app_localizations.dart` instead, because `flutter
gen-l10n` refused to run on a Windows dev machine whose checkout lived
inside OneDrive: Dart's `FileStat.modeString()` misreported every
directory in that checkout as read-only (`r-xr-xr-x`), so the tool
believed `lib/l10n` wasn't writable. That machine's checkout has since
moved outside OneDrive, so codegen now works there too — the hand-written
mirror was removed and real codegen restored (#061 follow-up). If this
ever resurfaces on some other machine, moving the checkout off a
cloud-sync folder is the actual fix; falling back to a hand-written mirror
is a last resort, not a preference.

## Direct-instantiation imports in tests

Most tests get `AppLocalizations` via `AppLocalizations.of(context)`
inside a pumped widget tree. A few pure-logic tests instead instantiate a
locale directly (no widget tree needed) — that needs importing the
specific generated locale file, since `app_localizations.dart` doesn't
re-export them:

```dart
import 'package:fox_streak_app/l10n/app_localizations_en.dart';
...
final l10n = AppLocalizationsEn();
```
