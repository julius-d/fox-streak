name: new-issue
description: Create a new issue file
---

Ask the user for what the issue should be about.
Ask clarifying questions.
Suggest options how something could be realized, and ask for feedback.
When UI is changed or created think of how animations can be used to make the UX more vivid.

Every single requirement / acceptance criteria that will appear the in new issue file.
has to be discussed with the user and agreed from the user. The user shall understand all the pros and cos of the requirement.

The issue file should not be about how something is implemented, but only about the product requirements and how the UX should be.

Then put all this in a fresh issue file:
Check in the /issues folder and the /issues/done what is the highest available issue ID.

Commit the issue file with a message like: `issue(123): add new issue for new question type`
